# SessionProject and EventPlanner

`SessionProject` resolves one scene of a validated `SessionDocument` (v3; v2 documents are migrated on read). It keeps the scene's immutable layers, master gain, transport and document seed. The default scene is used unless a scene ID is supplied. It contains no runtime transport state.

`EventPlanner(project).plan(fromBeat, toBeat)` takes non-negative absolute integer ticks (960 per quarter note) and returns immutable `PlannedRhythmEvent`s in `[fromBeat, toBeat)`. It expands each layer's own period only near the requested window; the practice cycle does not constrain the period, and no common LCM cycle is built. Events are sorted by tick, then scene layer index, then step index.

For each enabled step, the exact local position is `period * stepIndex / stepCount`. Eighth swing delays odd half-beat grid points by `amount * 1/4` beat; sixteenth swing delays odd quarter-beat grid points by `amount * 1/8` beat. Swing is applied before phase. `phaseSteps` adds `period * phaseSteps / stepCount`, and the result wraps within the period. Each occurrence adds an integer multiple of the period. The final exact rational position is rounded **once** to the nearest tick, with halves rounded up. No previous event's rounded tick is reused. The error is at most half a tick (about 0.26 ms at 120 BPM). Window membership uses this rounded tick, so adjacent windows agree with a whole window, including for step periods outside the tick grid.

Muted layers emit nothing. If at least one unmuted layer is soloed, only those soloed layers emit. Disabled steps emit nothing. An event carries `velocity`, `accent`, layer gain, master gain and pan separately. The planner does not change velocity for accents or perform audio gain staging. The layer's `instrumentId` and `pitch` (MIDI note 24..107) come with each event; the planner neither resolves the instrument nor converts the pitch to a frequency. Drones and reference clicks are outside this rhythm planner.

Probability is stateless and independent of window size. Starting with the document's uint32 seed, for each of `(layerIndex, stepIndex, cycleIndex)` in that order, compute `hash = ((hash XOR coordinate) * 0x01000193) mod 2^32`. Multiplication is implemented from 16-bit halves so it has the same result on Dart VM and web. A step plays if `hash / 2^32 < probability`; probability zero and one are handled exactly. This is a mobile core decision: the web laboratory currently has no probability or seed decision in `src/domain` or `src/audio`. Changing this algorithm would change a session's rhythm and requires a contract decision and updated known-value tests.

`eventId = (cycleIndex * 32 + stepIndex) * 4 + layerIndex`. The IDs are unique for document limits (up to 32 steps and 4 layers) and stable across planning windows. They are not the hand-authored IDs in the C0 fixtures. The fixture tests compare beat ticks and layer order; fixture sound names are also hand-authored labels, not instrument ids. The scheduler adapter from this core event to its C0 `PlannedVoiceEvent`, including gain staging, is a later task.

Tempo automation, runtime scene switching, quantized edits, dropout, drone scheduling, reference click scheduling and platform audio timestamps are outside this module.
